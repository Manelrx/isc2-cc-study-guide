Domain 5: Security Operations (18%)

This domain focuses on the practical application of security concepts through ongoing operations. It covers how data is secured, systems are hardened, security policies are implemented and maintained, and how security awareness is fostered within an organization to protect against threats and ensure operational resilience.

Explicação em Português

Este domínio foca na aplicação prática de conceitos de segurança através de operações contínuas. Abrange como os dados são protegidos, os sistemas são reforçados (hardening), as políticas de segurança são implementadas e mantidas, e como a conscientização sobre segurança é promovida dentro de uma organização para proteger contra ameaças e garantir a resiliência operacional.

5.1 Understand data security

Data security involves protecting digital data from unauthorized access, corruption, or theft throughout its entire lifecycle. Key aspects include encryption, proper data handling, and monitoring.

Explicação em Português

A segurança de dados envolve proteger dados digitais contra acesso não autorizado, corrupção ou roubo durante todo o seu ciclo de vida. Aspectos chave incluem criptografia, manuseio adequado de dados e monitoramento.

Encryption

The process of converting plaintext data into ciphertext using an algorithm and a key, making it unreadable to unauthorized parties. It protects data confidentiality.

  • Symmetric Encryption: Uses the *same* key for both encryption and decryption. Faster but requires secure key exchange.

    Algorithms: AES (Advanced Encryption Standard - common standard), DES (Data Encryption Standard - older, insecure), 3DES (Triple DES - slower, more secure than DES but being replaced by AES).

  • Asymmetric Encryption (Public-Key Cryptography): Uses *two* related keys: a public key for encryption and a private key for decryption. The public key can be shared widely, while the private key must be kept secret. Slower than symmetric but solves the key exchange problem and enables digital signatures.

    Algorithms: RSA (Rivest–Shamir–Adleman), ECC (Elliptic Curve Cryptography - more efficient for similar security levels).Uses: Secure key exchange (e.g., TLS/SSL handshake), digital signatures, non-repudiation.

  • Hashing: A one-way function that converts input data of any size into a fixed-size string of characters (the hash value or digest). It's computationally infeasible to reverse the process or find two different inputs that produce the same hash (collision resistance - though weaknesses exist in older algorithms). Primarily used for integrity verification, not confidentiality.

    Algorithms: MD5 (Message Digest 5 - insecure due to collisions, avoid), SHA-1 (Secure Hash Algorithm 1 - deprecated, weak), SHA-2 family (SHA-256, SHA-512 - currently secure standard), SHA-3.

    Uses: Password storage (storing hash of password + salt), file integrity verification, digital signatures (hashing the message then encrypting the hash).

  • Data States: Encryption should be applied to data at rest (stored on disks, databases, backups), data in transit (moving across networks - e.g., TLS/SSL, VPNs), and sometimes data in use (while being processed - more complex, e.g., homomorphic encryption).

Explicação em Português

O processo de converter dados em texto claro (plaintext) para texto cifrado (ciphertext) usando um algoritmo e uma chave, tornando-os ilegíveis para partes não autorizadas. Protege a confidencialidade dos dados.

  • Criptografia Simétrica: Usa a *mesma* chave para criptografia e descriptografia. Mais rápida, mas requer troca segura de chaves.

    Algoritmos: AES (Padrão de Criptografia Avançado - padrão comum), DES (Padrão de Criptografia de Dados - antigo, inseguro), 3DES (DES Triplo - mais lento, mais seguro que DES, mas sendo substituído por AES).

  • Criptografia Assimétrica (Criptografia de Chave Pública): Usa *duas* chaves relacionadas: uma chave pública para criptografia e uma chave privada para descriptografia. A chave pública pode ser compartilhada amplamente, enquanto a chave privada deve ser mantida em segredo. Mais lenta que a simétrica, mas resolve o problema da troca de chaves e permite assinaturas digitais.

    Algoritmos: RSA (Rivest–Shamir–Adleman), ECC (Criptografia de Curva Elíptica - mais eficiente para níveis de segurança semelhantes).Usos: Troca segura de chaves (ex: handshake TLS/SSL), assinaturas digitais, não-repúdio.

  • Hashing: Uma função unidirecional que converte dados de entrada de qualquer tamanho em uma string de caracteres de tamanho fixo (o valor hash ou digest). É computacionalmente inviável reverter o processo ou encontrar duas entradas diferentes que produzam o mesmo hash (resistência à colisão - embora existam fraquezas em algoritmos mais antigos). Usado principalmente para verificação de integridade, não confidencialidade.

    Algoritmos: MD5 (Message Digest 5 - inseguro devido a colisões, evitar), SHA-1 (Algoritmo de Hash Seguro 1 - obsoleto, fraco), família SHA-2 (SHA-256, SHA-512 - padrão seguro atual), SHA-3.

    Usos: Armazenamento de senhas (armazenar hash da senha + salt), verificação de integridade de arquivos, assinaturas digitais (fazer hash da mensagem e depois criptografar o hash).

  • Estados dos Dados: A criptografia deve ser aplicada a dados em repouso (armazenados em discos, bancos de dados, backups), dados em trânsito (movendo-se através de redes - ex: TLS/SSL, VPNs) e, às vezes, dados em uso (enquanto estão sendo processados - mais complexo, ex: criptografia homomórfica).

Data Handling

Policies and procedures for managing data throughout its lifecycle, from creation to destruction, ensuring security and compliance.

  • Classification: Categorizing data based on its sensitivity and criticality (e.g., Public, Internal, Confidential, Restricted). Classification determines the required level of protection.
  • Labeling: Marking data according to its classification level (physically or digitally) so users know how to handle it appropriately.
  • Handling Procedures: Specific rules for accessing, storing, transmitting, and destroying data based on its classification (e.g., encrypting confidential data, using secure transport methods).
  • Retention: Defining how long data must be kept based on business needs and legal/regulatory requirements. Data should not be kept longer than necessary.
  • Destruction: Securely disposing of data (physical or digital) when it's no longer needed, ensuring it cannot be recovered. Methods include shredding, degaussing (for magnetic media), physical destruction (pulverizing), and cryptographic erasure/shredding (overwriting data multiple times).

Explicação em Português

Políticas e procedimentos para gerenciar dados ao longo de seu ciclo de vida, desde a criação até a destruição, garantindo segurança e conformidade.

  • Classificação: Categorizar dados com base em sua sensibilidade e criticidade (ex: Público, Interno, Confidencial, Restrito). A classificação determina o nível de proteção necessário.
  • Rotulagem (Labeling): Marcar dados de acordo com seu nível de classificação (fisicamente ou digitalmente) para que os usuários saibam como manuseá-los adequadamente.
  • Procedimentos de Manuseio: Regras específicas para acessar, armazenar, transmitir e destruir dados com base em sua classificação (ex: criptografar dados confidenciais, usar métodos de transporte seguros).
  • Retenção: Definir por quanto tempo os dados devem ser mantidos com base nas necessidades do negócio e requisitos legais/regulatórios. Os dados não devem ser mantidos por mais tempo do que o necessário.
  • Destruição: Descartar dados com segurança (físicos ou digitais) quando não são mais necessários, garantindo que não possam ser recuperados. Métodos incluem fragmentação, desmagnetização (para mídias magnéticas), destruição física (pulverização) e apagamento/fragmentação criptográfica (sobrescrever dados várias vezes).

Logging and Monitoring Security Events

The process of collecting, analyzing, and responding to log data generated by systems, networks, and applications to detect security incidents, troubleshoot issues, and demonstrate compliance.

  • Log Sources: Firewalls, servers (OS logs, application logs), network devices (routers, switches), IDS/IPS, endpoints (desktops, laptops), databases, authentication systems.
  • Log Content: Timestamps, source/destination IP addresses, usernames, event types (login success/failure, file access, errors), actions performed.
  • Log Management: Centralized collection (using tools like Syslog), secure storage (preventing tampering), retention according to policy, and analysis.
  • Monitoring Tools:
    • SIEM (Security Information and Event Management): Aggregates log data from multiple sources, correlates events to identify potential threats, provides real-time alerting, and facilitates analysis and reporting.
    • IDS/IPS: Monitor traffic for known attack patterns or anomalies.
  • Purpose: Incident detection and investigation, compliance auditing, troubleshooting, understanding system behavior, providing evidence for forensics.

Explicação em Português

O processo de coletar, analisar e responder a dados de log gerados por sistemas, redes e aplicações para detectar incidentes de segurança, solucionar problemas e demonstrar conformidade.

  • Fontes de Log: Firewalls, servidores (logs do SO, logs de aplicação), dispositivos de rede (roteadores, switches), IDS/IPS, endpoints (desktops, laptops), bancos de dados, sistemas de autenticação.
  • Conteúdo do Log: Timestamps, endereços IP de origem/destino, nomes de usuário, tipos de evento (sucesso/falha de login, acesso a arquivos, erros), ações realizadas.
  • Gerenciamento de Logs: Coleta centralizada (usando ferramentas como Syslog), armazenamento seguro (prevenindo adulteração), retenção de acordo com a política e análise.
  • Ferramentas de Monitoramento:
    • SIEM (Gerenciamento de Informações e Eventos de Segurança): Agrega dados de log de múltiplas fontes, correlaciona eventos para identificar ameaças potenciais, fornece alertas em tempo real e facilita análise e relatórios.
    • IDS/IPS: Monitoram o tráfego em busca de padrões de ataque conhecidos ou anomalias.
  • Propósito: Detecção e investigação de incidentes, auditoria de conformidade, solução de problemas, compreensão do comportamento do sistema, fornecimento de evidências para forense.

5.2 Understand system hardening

System hardening is the process of securing a system by reducing its surface of vulnerability. A hardened system minimizes security risks by removing unnecessary software, disabling unused services, changing default settings, and applying security configurations.

Explicação em Português

O hardening de sistema é o processo de proteger um sistema reduzindo sua superfície de vulnerabilidade. Um sistema reforçado minimiza os riscos de segurança removendo software desnecessário, desabilitando serviços não utilizados, alterando configurações padrão e aplicando configurações de segurança.

Configuration Management

The process for establishing and maintaining consistency of a product's performance, functional, and physical attributes with its requirements, design, and operational information throughout its life. In security, this involves managing secure configurations.

  • Baselines: Establishing a standardized, secure starting configuration for systems (OS, applications, network devices). Deviations from the baseline should be managed through a change control process. Benchmarks from organizations like CIS (Center for Internet Security) provide guidance.
  • Updates: Regularly applying software updates provided by vendors. These often include security fixes (patches) for known vulnerabilities, bug fixes, and sometimes new features.
  • Patches: Specific pieces of code designed to fix security vulnerabilities or bugs in software. Patch management involves identifying needed patches, testing them, deploying them, and verifying installation. Timely patching is critical.
  • Hardening Techniques:
    • Removing or disabling unnecessary services, protocols, and software.
    • Changing default usernames and passwords.
    • Configuring strong password policies.
    • Applying the principle of least privilege for user accounts and services.
    • Configuring firewall rules (host-based and network).
    • Enabling security logging and monitoring.
    • Securing file permissions.

Explicação em Português

O processo para estabelecer e manter a consistência do desempenho, atributos funcionais e físicos de um produto com seus requisitos, design e informações operacionais ao longo de sua vida. Em segurança, isso envolve o gerenciamento de configurações seguras.

  • Baselines (Linhas de Base): Estabelecer uma configuração inicial padronizada e segura para sistemas (SO, aplicações, dispositivos de rede). Desvios da linha de base devem ser gerenciados através de um processo de controle de mudanças. Benchmarks de organizações como o CIS (Center for Internet Security) fornecem orientação.
  • Atualizações (Updates): Aplicar regularmente atualizações de software fornecidas pelos fornecedores. Estas frequentemente incluem correções de segurança (patches) para vulnerabilidades conhecidas, correções de bugs e, às vezes, novos recursos.
  • Patches: Pedaços específicos de código projetados para corrigir vulnerabilidades de segurança ou bugs em software. O gerenciamento de patches envolve identificar patches necessários, testá-los, implantá-los e verificar a instalação. A aplicação oportuna de patches é crítica.
  • Técnicas de Hardening:
    • Remover ou desabilitar serviços, protocolos e software desnecessários.
    • Alterar nomes de usuário e senhas padrão.
    • Configurar políticas de senha fortes.
    • Aplicar o princípio do menor privilégio para contas de usuário e serviços.
    • Configurar regras de firewall (baseado em host e rede).
    • Habilitar log e monitoramento de segurança.
    • Proteger permissões de arquivo.

5.3 Understand best practice security policies

Security policies are high-level documents that outline an organization's security posture, rules, and expectations. They provide the foundation for procedures, standards, and guidelines.

Explicação em Português

Políticas de segurança são documentos de alto nível que descrevem a postura de segurança, regras e expectativas de uma organização. Elas fornecem a base para procedimentos, padrões e diretrizes.

Common Security Policies

  • Data Handling Policy: Defines requirements for classifying, labeling, storing, transmitting, and destroying data based on sensitivity (links back to 5.1).
  • Password Policy: Specifies requirements for password complexity (length, character types), history (preventing reuse), expiration, and storage (hashed and salted).
  • Acceptable Use Policy (AUP): Defines acceptable and unacceptable uses of organizational resources (computers, networks, internet access, email). Users typically must agree to the AUP before being granted access.
  • Bring Your Own Device (BYOD) Policy: Outlines rules and security requirements for employees using personal devices (smartphones, laptops) for work purposes (e.g., required security controls, data segregation, remote wipe capabilities).
  • Change Management Policy: Defines the formal process for requesting, reviewing, approving, implementing, and documenting changes to IT systems and infrastructure to minimize disruption and security risks. Includes steps like testing and rollback plans.
  • Privacy Policy: Describes how the organization collects, uses, stores, and protects personal information, often required by regulations like GDPR (links back to 5.1).
  • Remote Access Policy: Defines rules and security requirements for accessing organizational resources remotely (e.g., required VPN usage, endpoint security checks).
  • Incident Response Policy: High-level document outlining the organization's approach to handling security incidents, including roles, responsibilities, and reporting requirements (links to IRP in Domain 2).

Explicação em Português

  • Política de Manuseio de Dados: Define requisitos para classificar, rotular, armazenar, transmitir e destruir dados com base na sensibilidade (liga de volta ao 5.1).
  • Política de Senha: Especifica requisitos para complexidade de senha (comprimento, tipos de caracteres), histórico (prevenindo reutilização), expiração e armazenamento (hashed e salted).
  • Política de Uso Aceitável (PUA / AUP): Define usos aceitáveis e inaceitáveis de recursos organizacionais (computadores, redes, acesso à internet, e-mail). Os usuários geralmente devem concordar com a AUP antes de receberem acesso.
  • Política Traga Seu Próprio Dispositivo (BYOD): Descreve regras e requisitos de segurança para funcionários que usam dispositivos pessoais (smartphones, laptops) para fins de trabalho (ex: controles de segurança exigidos, segregação de dados, capacidades de limpeza remota).
  • Política de Gerenciamento de Mudanças: Define o processo formal para solicitar, revisar, aprovar, implementar e documentar mudanças em sistemas e infraestrutura de TI para minimizar interrupções e riscos de segurança. Inclui etapas como testes e planos de rollback.
  • Política de Privacidade: Descreve como a organização coleta, usa, armazena e protege informações pessoais, frequentemente exigida por regulamentos como o GDPR (liga de volta ao 5.1).
  • Política de Acesso Remoto: Define regras e requisitos de segurança para acessar recursos organizacionais remotamente (ex: uso obrigatório de VPN, verificações de segurança do endpoint).
  • Política de Resposta a Incidentes: Documento de alto nível que descreve a abordagem da organização para lidar com incidentes de segurança, incluindo papéis, responsabilidades e requisitos de notificação (liga ao IRP no Domínio 2).

5.4 Understand security awareness training

Security awareness training aims to educate users about security threats, best practices, and organizational policies to modify behavior and reduce human error, which is often a significant factor in security breaches.

Explicação em Português

O treinamento de conscientização em segurança visa educar os usuários sobre ameaças de segurança, melhores práticas e políticas organizacionais para modificar o comportamento e reduzir o erro humano, que frequentemente é um fator significativo em violações de segurança.

Purpose/Concepts

The main goal is to make security a part of the organizational culture and empower users to be the first line of defense.

Key Topics Covered:

  • Social Engineering: Recognizing and resisting manipulation tactics used to trick individuals into revealing sensitive information or performing actions. Includes phishing (email), vishing (voice), smishing (SMS), pretexting, baiting, tailgating.
  • Password Protection: Creating strong, unique passwords/passphrases, using password managers, understanding MFA importance, not sharing credentials.
  • Malware Awareness: Identifying suspicious emails, attachments, links, and websites; understanding how malware spreads.
  • Data Handling: Understanding data classification, proper handling of sensitive information, secure data disposal.
  • Physical Security: Securing workspaces, locking screens, reporting suspicious individuals, proper badge usage.
  • Acceptable Use Policy (AUP): Reinforcing rules about using company resources.
  • Incident Reporting: Knowing how and when to report suspected security incidents.
  • Remote Work Security: Securing home networks, using VPNs, protecting devices outside the office.

Explicação em Português

O objetivo principal é tornar a segurança parte da cultura organizacional e capacitar os usuários a serem a primeira linha de defesa.

Tópicos Chave Abordados:

  • Engenharia Social: Reconhecer e resistir a táticas de manipulação usadas para enganar indivíduos a revelar informações sensíveis ou realizar ações. Inclui phishing (e-mail), vishing (voz), smishing (SMS), pretexting, baiting, tailgating (carona).
  • Proteção de Senha: Criar senhas/frases secretas fortes e únicas, usar gerenciadores de senha, entender a importância da MFA, não compartilhar credenciais.
  • Conscientização sobre Malware: Identificar e-mails, anexos, links e sites suspeitos; entender como o malware se espalha.
  • Manuseio de Dados: Entender a classificação de dados, manuseio adequado de informações sensíveis, descarte seguro de dados.
  • Segurança Física: Proteger espaços de trabalho, bloquear telas, relatar indivíduos suspeitos, uso adequado de crachás.
  • Política de Uso Aceitável (PUA): Reforçar regras sobre o uso de recursos da empresa.
  • Relato de Incidentes: Saber como e quando relatar incidentes de segurança suspeitos.
  • Segurança no Trabalho Remoto: Proteger redes domésticas, usar VPNs, proteger dispositivos fora do escritório.

Importance

Humans are often the weakest link in security. Awareness training is vital because it:

  • Reduces the likelihood of successful social engineering attacks.
  • Promotes secure behaviors (e.g., strong password practices).
  • Helps users identify and report potential threats early.
  • Ensures compliance with regulations that mandate security training.
  • Fosters a security-conscious culture within the organization.
  • Reduces accidental data breaches or policy violations.

Effective training should be ongoing, engaging, relevant to users' roles, and reinforced regularly (e.g., through phishing simulations, newsletters, periodic refreshers).

Explicação em Português

Os humanos são frequentemente o elo mais fraco na segurança. O treinamento de conscientização é vital porque:

  • Reduz a probabilidade de sucesso de ataques de engenharia social.
  • Promove comportamentos seguros (ex: práticas de senha fortes).
  • Ajuda os usuários a identificar e relatar ameaças potenciais precocemente.
  • Garante a conformidade com regulamentos que exigem treinamento de segurança.
  • Fomenta uma cultura consciente de segurança dentro da organização.
  • Reduz violações acidentais de dados ou violações de políticas.

Treinamento eficaz deve ser contínuo, envolvente, relevante para as funções dos usuários e reforçado regularmente (ex: através de simulações de phishing, newsletters, atualizações periódicas).
