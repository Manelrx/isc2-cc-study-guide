Domain 4: Network Security (24%)

This domain delves into the essential concepts of computer networking and the security measures required to protect network infrastructure and data communications. It covers network models, common protocols, network devices, security architectures, and prevalent threats and countermeasures.

Explicação em Português

Este domínio aprofunda-se nos conceitos essenciais de redes de computadores e nas medidas de segurança necessárias para proteger a infraestrutura de rede e as comunicações de dados. Abrange modelos de rede, protocolos comuns, dispositivos de rede, arquiteturas de segurança e ameaças e contramedidas prevalentes.

4.1 Understand computer networking

Understanding the fundamentals of how computers communicate over networks is crucial for implementing effective security.

Explicação em Português

Compreender os fundamentos de como os computadores se comunicam em redes é crucial para implementar segurança eficaz.

Networks (Models and Protocols)

  • OSI Model (Open Systems Interconnection): A 7-layer conceptual model:
    1. Physical: Transmission of raw bits (cables, hubs).
    2. Data Link: Framing, MAC addresses, error detection (switches, Ethernet).
    3. Network: Logical addressing (IP), routing, path determination (routers, IP).
    4. Transport: End-to-end connections, reliability, flow control (TCP, UDP).
    5. Session: Managing communication sessions between applications.
    6. Presentation: Data formatting, encryption, compression.
    7. Application: Network services for end-user applications (HTTP, FTP, SMTP).
  • TCP/IP Model (Transmission Control Protocol/Internet Protocol): A 4-layer practical model used for the internet:
    1. Network Interface/Link: Combines OSI Physical and Data Link layers.
    2. Internet: Corresponds to OSI Network layer (IP, ICMP, ARP).
    3. Transport: Corresponds to OSI Transport layer (TCP, UDP).
    4. Application: Combines OSI Session, Presentation, and Application layers (HTTP, DNS, FTP).
  • IP Addresses:
    • IPv4: 32-bit addresses (e.g., 192.168.1.1), commonly used but facing exhaustion. Uses subnet masks (e.g., 255.255.255.0) to define network/host portions.
    • IPv6: 128-bit addresses (e.g., 2001:0db8:85a3:0000:0000:8a2e:0370:7334), providing a vastly larger address space and built-in features like IPsec support (optional in IPv4).
  • WiFi (Wireless Fidelity): Standards for wireless local area networks (WLANs) based on IEEE 802.11.
    • Security Protocols: WEP (Wired Equivalent Privacy - insecure, deprecated), WPA (Wi-Fi Protected Access), WPA2 (stronger, uses AES), WPA3 (latest standard with enhanced security features like individualized data encryption).

Explicação em Português

  • Modelo OSI: Um modelo conceitual de 7 camadas:
    1. Física: Transmissão de bits brutos (cabos, hubs).
    2. Enlace de Dados: Enquadramento, endereços MAC, detecção de erros (switches, Ethernet).
    3. Rede: Endereçamento lógico (IP), roteamento, determinação de caminho (roteadores, IP).
    4. Transporte: Conexões fim-a-fim, confiabilidade, controle de fluxo (TCP, UDP).
    5. Sessão: Gerenciamento de sessões de comunicação entre aplicações.
    6. Apresentação: Formatação de dados, criptografia, compressão.
    7. Aplicação: Serviços de rede para aplicações do usuário final (HTTP, FTP, SMTP).
  • Modelo TCP/IP: Um modelo prático de 4 camadas usado para a internet:
    1. Interface de Rede/Enlace: Combina as camadas Física e de Enlace de Dados do OSI.
    2. Internet: Corresponde à camada de Rede do OSI (IP, ICMP, ARP).
    3. Transporte: Corresponde à camada de Transporte do OSI (TCP, UDP).
    4. Aplicação: Combina as camadas de Sessão, Apresentação e Aplicação do OSI (HTTP, DNS, FTP).
  • Endereços IP:
    • IPv4: Endereços de 32 bits (ex: 192.168.1.1), comumente usados, mas enfrentando esgotamento. Usa máscaras de sub-rede (ex: 255.255.255.0) para definir porções de rede/host.
    • IPv6: Endereços de 128 bits (ex: 2001:0db8:85a3:0000:0000:8a2e:0370:7334), fornecendo um espaço de endereço vastamente maior e recursos integrados como suporte a IPsec (opcional no IPv4).
  • WiFi (Wireless Fidelity): Padrões para redes locais sem fio (WLANs) baseados em IEEE 802.11.
    • Protocolos de Segurança: WEP (Wired Equivalent Privacy - inseguro, obsoleto), WPA (Wi-Fi Protected Access), WPA2 (mais forte, usa AES), WPA3 (padrão mais recente com recursos de segurança aprimorados como criptografia de dados individualizada).

Ports

Logical endpoints for communication used by the Transport layer (TCP and UDP) to differentiate between different services or applications running on the same host. Ports are numbered from 0 to 65535.

Common Ports (Well-Known Ports 0-1023):

  • 20/21 (TCP): FTP (File Transfer Protocol) - 20 for data, 21 for control.
  • 22 (TCP): SSH (Secure Shell) - Secure remote login and other secure network services.
  • 23 (TCP): Telnet - Unsecure remote login (avoid using).
  • 25 (TCP): SMTP (Simple Mail Transfer Protocol) - Email transmission.
  • 53 (TCP/UDP): DNS (Domain Name System) - Translates domain names to IP addresses.
  • 80 (TCP): HTTP (Hypertext Transfer Protocol) - Unsecure web traffic.
  • 110 (TCP): POP3 (Post Office Protocol v3) - Email retrieval.
  • 143 (TCP): IMAP (Internet Message Access Protocol) - Email retrieval.
  • 443 (TCP): HTTPS (HTTP Secure) - Secure web traffic (HTTP over TLS/SSL).
  • 3389 (TCP): RDP (Remote Desktop Protocol) - Remote desktop access for Windows.

Firewalls often filter traffic based on port numbers.

Pontos finais lógicos para comunicação usados pela camada de Transporte (TCP e UDP) para diferenciar entre diferentes serviços ou aplicações rodando no mesmo host. As portas são numeradas de 0 a 65535.

Portas Comuns (Portas Bem Conhecidas 0-1023):

  • 20/21 (TCP): FTP (Protocolo de Transferência de Arquivos) - 20 para dados, 21 para controle.
  • 22 (TCP): SSH (Secure Shell) - Login remoto seguro e outros serviços de rede seguros.
  • 23 (TCP): Telnet - Login remoto inseguro (evitar usar).
  • 25 (TCP): SMTP (Protocolo de Transferência de Correio Simples) - Transmissão de e-mail.
  • 53 (TCP/UDP): DNS (Sistema de Nomes de Domínio) - Traduz nomes de domínio para endereços IP.
  • 80 (TCP): HTTP (Protocolo de Transferência de Hipertexto) - Tráfego web inseguro.
  • 110 (TCP): POP3 (Post Office Protocol v3) - Recuperação de e-mail.
  • 143 (TCP): IMAP (Protocolo de Acesso a Mensagens da Internet) - Recuperação de e-mail.
  • 443 (TCP): HTTPS (HTTP Seguro) - Tráfego web seguro (HTTP sobre TLS/SSL).
  • 3389 (TCP): RDP (Protocolo de Área de Trabalho Remota) - Acesso remoto à área de trabalho para Windows.

Firewalls frequentemente filtram tráfego com base nos números das portas.

Applications

Software programs that use the network to provide services to users (e.g., web browsers, email clients, file sharing applications). Security considerations involve securing the application itself (secure coding, input validation) and the protocols it uses (e.g., using HTTPS instead of HTTP).

Explicação em Português

Programas de software que usam a rede para fornecer serviços aos usuários (ex: navegadores web, clientes de e-mail, aplicações de compartilhamento de arquivos). Considerações de segurança envolvem proteger a própria aplicação (codificação segura, validação de entrada) e os protocolos que ela usa (ex: usar HTTPS em vez de HTTP).

4.2 Understand network threats and attacks

Recognizing common network threats and attack vectors is essential for implementing appropriate defenses.

Explicação em Português

Reconhecer ameaças de rede comuns e vetores de ataque é essencial para implementar defesas apropriadas.

Types of Threats

  • DDoS (Distributed Denial-of-Service): Aims to make a service unavailable by overwhelming it with traffic from numerous compromised systems (botnet). Types include volumetric attacks (bandwidth saturation), protocol attacks (exploiting protocol weaknesses), and application layer attacks (targeting application resources).
  • Virus: Malicious code requiring a host program to run and user action (e.g., opening a file) to spread. Can corrupt data, steal information, etc.
  • Worm: Self-propagating malware that exploits vulnerabilities to spread across networks automatically without user interaction. Can consume bandwidth or install backdoors.
  • Trojan (Trojan Horse): Malware disguised as legitimate software. Users are tricked into installing it. Can provide remote access, steal data, or download other malware.
  • Man-in-the-Middle (MITM): Attacker intercepts communication between two parties, potentially eavesdropping or modifying data. Common in unsecured Wi-Fi networks. Techniques include ARP spoofing, DNS spoofing, SSL stripping.
  • Side-Channel Attack: Exploits information gained from the physical implementation of a system, rather than direct code vulnerabilities (e.g., analyzing power consumption, timing information, or electromagnetic leaks to infer cryptographic keys or data).
  • Others: Phishing, Spear Phishing, Ransomware, SQL Injection, Cross-Site Scripting (XSS), Sniffing (capturing network traffic), Spoofing (IP, MAC, email).

Explicação em Português

  • DDoS: Visa tornar um serviço indisponível sobrecarregando-o com tráfego de numerosos sistemas comprometidos (botnet). Tipos incluem ataques volumétricos (saturação de largura de banda), ataques de protocolo (explorando fraquezas de protocolo) e ataques de camada de aplicação (visando recursos da aplicação).
  • Vírus: Código malicioso que requer um programa hospedeiro para rodar e ação do usuário (ex: abrir um arquivo) para se espalhar. Pode corromper dados, roubar informações, etc.
  • Worm: Malware autopropagável que explora vulnerabilidades para se espalhar por redes automaticamente sem interação do usuário. Pode consumir largura de banda ou instalar backdoors.
  • Trojan (Cavalo de Troia): Malware disfarçado de software legítimo. Usuários são enganados para instalá-lo. Pode fornecer acesso remoto, roubar dados ou baixar outro malware.
  • Man-in-the-Middle (MITM): Atacante intercepta a comunicação entre duas partes, potencialmente espionando ou modificando dados. Comum em redes Wi-Fi inseguras. Técnicas incluem ARP spoofing, DNS spoofing, SSL stripping.
  • Ataque de Canal Lateral (Side-Channel): Explora informações obtidas da implementação física de um sistema, em vez de vulnerabilidades diretas no código (ex: analisar consumo de energia, informações de tempo ou vazamentos eletromagnéticos para inferir chaves criptográficas ou dados).
  • Outros: Phishing, Spear Phishing, Ransomware, Injeção de SQL, Cross-Site Scripting (XSS), Sniffing (captura de tráfego de rede), Spoofing (IP, MAC, e-mail).

Identification (Detection)

Mechanisms to detect malicious activity or policy violations.

  • Intrusion Detection System (IDS): Monitors network traffic or system logs for suspicious patterns or known attack signatures. Generates alerts when potential incidents are detected but does not block traffic itself.
    • Network Intrusion Detection System (NIDS): Monitors traffic on the network segment it's connected to.
    • Host-based Intrusion Detection System (HIDS): Monitors activities on a specific host (e.g., system calls, file system changes, logs).
  • Log Analysis: Reviewing logs from firewalls, servers, applications, and network devices for anomalies or indicators of compromise (IoCs). Often centralized using SIEM systems.
  • Network Monitoring Tools: Tools like Wireshark (packet sniffer) or NetFlow analyzers help visualize and analyze network traffic patterns.

Explicação em Português

Mecanismos para detectar atividade maliciosa ou violações de política.

  • Sistema de Detecção de Intrusão (IDS): Monitora o tráfego de rede ou logs do sistema em busca de padrões suspeitos ou assinaturas de ataques conhecidos. Gera alertas quando incidentes potenciais são detectados, mas não bloqueia o tráfego por si só.
    • IDS de Rede (NIDS): Monitora o tráfego no segmento de rede ao qual está conectado.
    • IDS Baseado em Host (HIDS): Monitora atividades em um host específico (ex: chamadas de sistema, alterações no sistema de arquivos, logs).
  • Análise de Logs: Revisar logs de firewalls, servidores, aplicações e dispositivos de rede em busca de anomalias ou indicadores de comprometimento (IoCs). Frequentemente centralizada usando sistemas SIEM.
  • Ferramentas de Monitoramento de Rede: Ferramentas como Wireshark (sniffer de pacotes) ou analisadores NetFlow ajudam a visualizar e analisar padrões de tráfego de rede.

Prevention

Measures taken to stop attacks before they succeed.

  • Firewalls: Control traffic flow between networks based on rules (stateful inspection, proxy, next-generation firewalls - NGFW).
  • Intrusion Prevention System (IPS): Similar to IDS, but actively blocks or modifies malicious traffic it detects (can be NIPS or HIPS).
  • Antivirus/Anti-Malware: Scans files and processes for known malware signatures and heuristics (behavioral analysis) to block or quarantine threats.
  • Patch Management: Regularly applying updates and patches to operating systems and applications to fix known vulnerabilities exploited by malware.
  • Security Awareness Training: Educating users about threats like phishing and social engineering.
  • Strong Authentication & Access Control: Using MFA and applying the principle of least privilege.
  • Network Segmentation: Dividing the network into smaller, isolated zones to limit the spread of attacks.
  • Vulnerability Scans: Proactively scanning systems and networks for known weaknesses.

Explicação em Português

Medidas tomadas para impedir ataques antes que tenham sucesso.

  • Firewalls: Controlam o fluxo de tráfego entre redes com base em regras (inspeção de estado, proxy, firewalls de próxima geração - NGFW).
  • Sistema de Prevenção de Intrusão (IPS): Semelhante ao IDS, mas bloqueia ou modifica ativamente o tráfego malicioso que detecta (pode ser NIPS ou HIPS).
  • Antivírus/Anti-Malware: Varre arquivos e processos em busca de assinaturas de malware conhecidas e heurísticas (análise comportamental) para bloquear ou colocar ameaças em quarentena.
  • Gerenciamento de Patches: Aplicar regularmente atualizações e patches em sistemas operacionais e aplicações para corrigir vulnerabilidades conhecidas exploradas por malware.
  • Treinamento de Conscientização em Segurança: Educar usuários sobre ameaças como phishing e engenharia social.
  • Autenticação Forte e Controle de Acesso: Usar MFA e aplicar o princípio do menor privilégio.
  • Segmentação de Rede: Dividir a rede em zonas menores e isoladas para limitar a propagação de ataques.
  • Varreduras de Vulnerabilidade: Varredura proativa de sistemas e redes em busca de fraquezas conhecidas.

4.3 Understand network security infrastructure

This involves understanding the components and design principles used to build secure networks, both on-premises and in the cloud.

Explicação em Português

Isso envolve entender os componentes e princípios de design usados para construir redes seguras, tanto no local (on-premises) quanto na nuvem.

On-Premises Infrastructure Considerations

Securing the physical location and supporting infrastructure for network equipment.

  • Power: Redundant power supplies (UPS - Uninterruptible Power Supply), backup generators to ensure continuous operation during outages.
  • Data Center/Closets: Secure rooms housing servers and network equipment, with physical access controls, proper cable management, and environmental monitoring.
  • HVAC (Heating, Ventilation, and Air Conditioning): Maintaining appropriate temperature and humidity levels to prevent equipment overheating or damage.
  • Environmental Monitoring: Sensors for temperature, humidity, water leaks.
  • Fire Suppression: Systems using water, gas, or chemical agents to extinguish fires while minimizing damage to electronic equipment.
  • Redundancy: Implementing backup components (servers, network links, power supplies) to avoid single points of failure.
  • MOU/MOA (Memorandum of Understanding/Agreement): Formal agreements outlining responsibilities and terms, often used between organizations sharing infrastructure or services, though less directly related to infrastructure components themselves.

Explicação em Português

Proteger o local físico e a infraestrutura de suporte para equipamentos de rede.

  • Energia: Fontes de alimentação redundantes (UPS - No-break), geradores de backup para garantir operação contínua durante quedas de energia.
  • Data Center/Armários (Closets): Salas seguras que abrigam servidores e equipamentos de rede, com controles de acesso físico, gerenciamento adequado de cabos e monitoramento ambiental.
  • HVAC (Aquecimento, Ventilação e Ar Condicionado): Manter níveis apropriados de temperatura e umidade para prevenir superaquecimento ou danos aos equipamentos.
  • Monitoramento Ambiental: Sensores de temperatura, umidade, vazamentos de água.
  • Supressão de Incêndio: Sistemas que usam água, gás ou agentes químicos para extinguir incêndios minimizando danos a equipamentos eletrônicos.
  • Redundância: Implementar componentes de backup (servidores, links de rede, fontes de alimentação) para evitar pontos únicos de falha.
  • MOU/MOA (Memorando de Entendimento/Acordo): Acordos formais que descrevem responsabilidades e termos, frequentemente usados entre organizações que compartilham infraestrutura ou serviços, embora menos diretamente relacionados aos próprios componentes da infraestrutura.

Network Design Principles

Architectural approaches to building secure and resilient networks.

  • Network Segmentation: Dividing a network into smaller, isolated segments or zones to limit the impact of a breach in one segment on others. Methods include:
    • DMZ (Demilitarized Zone): A perimeter network segment separating internal networks from untrusted external networks (like the internet), often hosting public-facing servers (web, email).
    • VLAN (Virtual Local Area Network): Logically segmenting a physical network switch into multiple broadcast domains. Traffic between VLANs typically requires routing (and can be filtered by firewalls).
    • VPN (Virtual Private Network): Creates secure, encrypted tunnels over public networks for remote access or site-to-site connections.
    • Micro-segmentation: Applying granular security policies to individual workloads or applications, often within data centers or cloud environments, providing finer control than traditional network segmentation.
  • Defense in Depth: A layered security approach where multiple different security controls are implemented throughout the infrastructure. If one layer fails, others provide backup protection.
  • Network Access Control (NAC): Solutions that enforce security policies on devices attempting to access the network. Can check for compliance (e.g., updated antivirus, patches) before granting access, often using protocols like 802.1X. Important for managing access for diverse devices, including embedded systems and Internet of Things (IoT).

Explicação em Português

Abordagens arquitetônicas para construir redes seguras e resilientes.

  • Segmentação de Rede: Dividir uma rede em segmentos ou zonas menores e isoladas para limitar o impacto de uma violação em um segmento sobre os outros. Métodos incluem:
    • DMZ (Zona Desmilitarizada): Um segmento de rede de perímetro que separa redes internas de redes externas não confiáveis (como a internet), frequentemente hospedando servidores públicos (web, e-mail).
    • VLAN (Rede Local Virtual): Segmentar logicamente um switch de rede físico em múltiplos domínios de broadcast. O tráfego entre VLANs tipicamente requer roteamento (e pode ser filtrado por firewalls).
    • VPN (Rede Privada Virtual): Cria túneis seguros e criptografados sobre redes públicas para acesso remoto ou conexões site-a-site.
    • Micro-segmentação: Aplicar políticas de segurança granulares a cargas de trabalho ou aplicações individuais, frequentemente dentro de data centers ou ambientes de nuvem, fornecendo controle mais fino que a segmentação de rede tradicional.
  • Defesa em Profundidade: Uma abordagem de segurança em camadas onde múltiplos controles de segurança diferentes são implementados em toda a infraestrutura. Se uma camada falhar, outras fornecem proteção de backup.
  • Controle de Acesso à Rede (NAC): Soluções que impõem políticas de segurança em dispositivos que tentam acessar a rede. Pode verificar a conformidade (ex: antivírus atualizado, patches) antes de conceder acesso, frequentemente usando protocolos como 802.1X. Importante para gerenciar o acesso de dispositivos diversos, incluindo sistemas embarcados e Internet das Coisas (IoT).

Cloud Infrastructure Considerations

Understanding security aspects specific to cloud computing environments.

  • SLA (Service-Level Agreement): Contract between a cloud provider and customer defining service levels, performance metrics, uptime guarantees, and responsibilities (including security).
  • MSP (Managed Service Provider): A third-party company that remotely manages a customer's IT infrastructure and/or end-user systems, potentially including cloud security management.
  • Cloud Service Models (Shared Responsibility):
    • SaaS (Software as a Service): Provider manages infrastructure, OS, and application; customer manages user access and data (e.g., Gmail, Salesforce).
    • PaaS (Platform as a Service): Provider manages infrastructure and OS; customer manages applications and data (e.g., Heroku, AWS Elastic Beanstalk).
    • IaaS (Infrastructure as a Service): Provider manages underlying infrastructure (hardware, virtualization); customer manages OS, applications, and data (e.g., AWS EC2, Azure VMs).
  • Hybrid Cloud: A mix of on-premises infrastructure and public/private cloud services, requiring careful integration and consistent security policy enforcement across environments.
  • Cloud Security Controls: Security groups (cloud firewalls), Identity and Access Management (IAM), encryption services, logging and monitoring tools provided by the cloud provider.

Explicação em Português

Entender aspectos de segurança específicos para ambientes de computação em nuvem.

  • SLA (Acordo de Nível de Serviço): Contrato entre um provedor de nuvem e o cliente definindo níveis de serviço, métricas de desempenho, garantias de tempo de atividade e responsabilidades (incluindo segurança).
  • MSP (Provedor de Serviços Gerenciados): Uma empresa terceirizada que gerencia remotamente a infraestrutura de TI de um cliente e/ou sistemas de usuário final, potencialmente incluindo gerenciamento de segurança na nuvem.
  • Modelos de Serviço em Nuvem (Responsabilidade Compartilhada):
    • SaaS (Software como Serviço): Provedor gerencia infraestrutura, SO e aplicação; cliente gerencia acesso do usuário e dados (ex: Gmail, Salesforce).
    • PaaS (Plataforma como Serviço): Provedor gerencia infraestrutura e SO; cliente gerencia aplicações e dados (ex: Heroku, AWS Elastic Beanstalk).
    • IaaS (Infraestrutura como Serviço): Provedor gerencia infraestrutura subjacente (hardware, virtualização); cliente gerencia SO, aplicações e dados (ex: AWS EC2, Azure VMs).
  • Nuvem Híbrida: Uma mistura de infraestrutura local e serviços de nuvem pública/privada, exigindo integração cuidadosa e aplicação consistente de políticas de segurança entre os ambientes.
  • Controles de Segurança na Nuvem: Grupos de segurança (firewalls na nuvem), Gerenciamento de Identidade e Acesso (IAM), serviços de criptografia, ferramentas de log e monitoramento fornecidas pelo provedor de nuvem.
